Inkdown 1.2.0 reads PDF files, colours logs, follows files and web addresses as they grow, handles very large files properly, and has a new home page.

## Downloads

| Platform | File | Status |
| --- | --- | --- |
| Windows 10 / 11 x64, installer | `Inkdown-Setup.exe` | Stable |
| Windows x64, portable | `inkdown-windows-x64.exe` | Stable |
| Android 8+ (arm64, x86_64) | `inkdown-android.apk` | Beta |
| macOS 11+ universal | `Inkdown-macos-universal.dmg` | Preview |
| Linux x86_64 | `inkdown-linux-x86_64.tar.gz` | Preview |

`SHA256SUMS.txt` lists the checksum of every file. Windows 1.0.1 and later update
themselves (*Help > Check for Updates*). The Android package installs over 1.0.3 and later.

## PDF files

Inkdown now opens PDF files and shows their pages, with no browser or other program
involved.

- Pages are drawn in the background, one under another, fitted to the width of the window.
- Zoom with the buttons at the bottom, with Ctrl and the mouse wheel, or by pinching;
  the percentage button returns to *fit width*.
- A PDF is recognised by its content, so one under another file name opens too.
- PDF files are only read, never changed.

Password-protected PDF files cannot be opened yet. Selecting or searching text inside a
PDF, and writing PDF files without a browser, are not part of this release.

## Logs in colour

Log files are coloured by severity: errors red, warnings amber, INFO with a green level
and highlighted numbers, quoted text and `key=` names, DEBUG and TRACE dimmed, times in
grey. Stack traces take the colour of the entry they belong to.

- Common formats are understood: `2026-11-15 10:00:00 ERROR …`, `[info]`, `level=warn`,
  JSON lines with `"level":"error"`, syslog, and Android logcat.
- A file that reads like a log is coloured as one whatever it is called (`.log`, `.out`,
  `.txt`, or no extension).
- Each line is coloured on its own, so a log of several million lines is coloured as
  quickly as a small one.

## Follow: new lines as they are written

*View > Follow* (also in the command palette) keeps reading a file as other programs add
to it, like `tail -f`: new lines appear within a second and the view stays at the end.
Scroll or move up to read older lines without being pulled back; go to the end to follow
again. A followed file is refreshed even while Inkdown is in the background.

Only what was added is read, so following a large log costs almost nothing.

## Open from a web address

*File > Open from Web Address…* opens a document straight from an `http://` or
`https://` address: a log on a server, a README, a JSON or YAML file.

- The document is **refreshed while it is open** (every 3 seconds; set
  `"live_refresh_seconds"`, or turn it off with `"live_refresh": false`). The status bar
  shows when it was last checked; click it to refresh now.
- **Streams are shown as they arrive.** If the server keeps the connection open and
  goes on sending (a live log endpoint), every new line appears at once, for as long as
  the connection lasts. When the server closes it, Inkdown goes back to looking again.
- Inkdown asks the server only for what changed where the server supports it
  (`If-None-Match`, `Range`), and otherwise compares what it gets.
- A log is followed from its end. Markdown opens in Read mode.
- The document is read-only. *Save As* keeps a copy, which is then an ordinary file.
- Addresses can also be given on the command line: `inkdown https://example.com/app.log`.
- Tabs opened from the web come back on the next start.

Inkdown sends no account details with these requests. Addresses that need a login are
not supported yet.

## Large files

Measured on Windows 11 with the release build (24 logical processors, NVMe drive):

| File | Memory in 1.1 | Memory now | Peak while opening, 1.1 | Peak now |
| --- | --- | --- | --- | --- |
| Welcome page only | 119 MB | 119 MB | 120 MB | 120 MB |
| 10 MB log, 100 000 lines | 114 MB | 95 MB | 114 MB | 105 MB |
| 100 MB log, 820 000 lines | 216 MB | 196 MB | 366 MB | 206 MB |
| 500 MB log, 4.1 million lines | 680 MB | 656 MB | 1 631 MB | 667 MB |

- **Large files are read in the background.** The tab appears at once and the status bar
  shows progress; the rest of the window stays usable.
- **Text is decoded in pieces straight into the editor's buffer**, so the file, a decoded
  copy and the buffer no longer exist in memory at the same time.
- The size limit is now 2 GB on desktop (was 600 MB) and 256 MB on phones. A document needs
  about 1.3 times its size in memory.
- When a large file changes on disk, only what was added is read where possible.
- **Word wrap works on huge files.** Turning it on for the 500 MB log took 31 seconds and
  every edit after that 38 seconds; now it takes 0.8 seconds once and edits are instant.
  Rows are counted on all processor cores, and after an edit only the changed lines are
  counted again.
- **Find and Replace All cover the whole of a large file.** Before, a search stopped
  after 0.4 seconds or 100 000 matches without saying so, and copied the whole document
  on every keystroke. Files over 4 MB are now searched in the background, piece by piece:
  the counter shows *searching…*, results fill in as they are found, and Replace All
  waits until every match is known. In the 500 MB log, all 173 020 matches of a word
  were found in under a second while the window stayed smooth; Replace All changed all
  of them in one step, and one Undo brought them back.
- Idle, Inkdown uses no measurable processor time (0.2 % of one core or less in all four
  cases). Scrolling, jumping to the end and typing in the 500 MB file build each frame in
  about 5 ms.
- Colouring: logs are coloured instantly at any size. Other languages show approximate
  colours at once while an exact pass runs in the background; on a 60 MB source file of
  2.8 million lines that pass takes more than half a minute, and until it arrives colours
  inside long multi-line comments or strings can be wrong.

## Home page

The page shown when no document is open has been redone.

- The actions are tiles: New document, Open file, Open folder, From template, Web address.
- **Recent files are rows that say what they are**: icon, name, folder (with the home
  folder shortened to `~`), size and when the file last changed. Files that no longer
  exist are marked *not found*.
- A filter box narrows the list, the × on a row removes it, *Clear* empties the list.
- Recent folders have their own section.

## Closing

- Closing a tab with unsaved changes asks, as before.
- Closing the window does not ask: unsaved work is kept and is there again on the next
  start. It asks only about what could not be kept that way: documents too large for a
  draft file (over 32 MB), or everything when `"hot_exit"` is switched off. Until now the
  window closed without a word in those cases too, and the changes were lost.

## Fixes

- The PDF, picture and Avro readers are chosen by the content of a file where its name
  does not say.

## Known limits

- Files larger than memory allows cannot be opened; Inkdown does not page text from disk.
- In a file searched in the background, a match cannot span the border between two
  pieces (4 MB each, always cut at the end of a line), and at most 5 million matches are
  kept.
- Following needs a UTF-8 file. Files in other encodings are read again in full when
  they change.
- Android scrolling could again only be checked on a slow emulator; *Help > About
  Inkdown* shows frame timings that are useful in a report.
- The rest is unchanged from [1.1.0](v1.1.0.md).
