Inkdown 1.3.0 writes PDF files without a browser, searches and selects text inside PDF files, and has been tested on a real Android phone, on Linux and on macOS.

## Downloads

| Platform | File | Status |
| --- | --- | --- |
| Windows 10 / 11 x64, installer | `Inkdown-Setup.exe` | Stable |
| Windows x64, portable | `inkdown-windows-x64.exe` | Stable |
| Android 8+ (arm64, x86_64) | `inkdown-android.apk` | Beta, tested on a Pixel 10 Pro |
| macOS 11+ universal | `Inkdown-macos-universal.dmg` | Preview, UI checks run on a Mac in CI |
| Linux x86_64 | `inkdown-linux-x86_64.tar.gz` | Preview, UI checks run in a container |

`SHA256SUMS.txt` lists the checksum of every file. Windows 1.0.1 and later update
themselves (*Help > Check for Updates*). The Android package installs over 1.0.3 and later.

## PDF export without a browser

*Export > PDF* no longer needs Microsoft Edge or Chrome. Inkdown lays the document out on
A4 pages and writes the PDF itself, the same way on Windows, macOS, Linux and Android.

- **Real text** in the bundled fonts, so the PDF can be searched and copied from; fonts
  of the system are used for characters the bundled ones lack (emoji, other scripts).
- Headings become **bookmarks**, links can be clicked, pages are numbered.
- Tables, code blocks, quotes and callouts, task lists, footnotes, front matter,
  pictures; diagrams (Mermaid, Graphviz, charts, SVG) and formulas are placed as
  sharp pictures.
- **Source code and plain text** can be exported too, as a listing in the code font
  (command palette: *Export: PDF*).
- On Android the file goes to `Downloads/Inkdown`; *Print* is a separate entry.

The earlier way, through an installed browser, is still there as *Export: PDF through a
Browser* in the command palette, for a page that looks exactly like the HTML export.

On Linux this fixes PDF export outright: on a system without a browser it used to fail.

## Reading PDF files

- **Find** (Ctrl+F, or the magnifier on a phone) searches the text of every page, marks
  the matches and steps through them.
- **Select and copy** with the mouse: drag over text, or double-click a word, then
  Ctrl+C. The right-click menu also copies a whole page.
- **Password-protected files** ask for their password. It is used for the session and
  not stored.

## Large files

- **The lines on screen get their true colours at once.** After jumping to the end of a
  60 MB source file (2.8 million lines), colours used to be approximate until a pass
  from the top of the file reached them, about four minutes later. Now the parser starts
  some two thousand lines above what is shown, which gives the true colours in 0.3
  seconds; only inside a comment or string longer than that can they still be wrong
  until the full pass arrives.
- The full pass runs on several processor cores and takes about 42 seconds for that
  file, instead of roughly 190 to 240.
- In logs, the first line of a stack trace (`java.lang.IllegalStateException: boom`)
  now takes the colour of its entry, like the frames under it.

## Android

Tested on a Pixel 10 Pro (Android 17) for the first time; until now only an emulator
had been used.

- **High refresh rate.** Inkdown now asks for the fastest rate the screen has. On the
  test phone it ran at about 110 frames a second with *Smooth display* on, and at a
  steady 60 with it off (then the phone shows 60 to every app). Whether earlier
  versions were held at 60 with the setting on was not measured.
- **A phone held sideways keeps the phone layout.** It used to switch to the desktop
  layout, which left three lines of text visible.
- **The magnifier finds in the document**, in PDF files too. It used to open the file
  picker.
- No on-screen keyboard over a document that cannot be edited.
- A note filed while still called "Untitled" takes its name from its first line.
- Exported PDF files are saved as PDF (Android used to add `.txt` to the name).

## Tested on Linux and macOS

The scripted checks of the real window, which so far ran on Windows only, now run on:

- **Linux**, in a container with a virtual display and software OpenGL
  (`make linux-uitest`, and in CI for every change): 154 checks.
- **macOS**, on a Mac in CI: 142 checks.

Timing checks and the Windows installer checks are left out on those systems. What this
does not cover is use by a person: opening files from Finder, signing prompts and the
feel of a trackpad are still untested on a Mac.

## Known limits

- PDF export: text is set left-aligned in one column; a table row or a picture is not
  split across pages; links to places inside the document are not active.
- Selecting text in a PDF needs a mouse; on a phone the text can be searched but not
  yet selected.
- Files larger than memory allows cannot be opened.
- The rest is unchanged from [1.2.0](v1.2.0.md).

## Testing for this release

- Unit tests on Windows, macOS and Linux (CI): 61, with new ones that export a document
  and read the PDF back, that compare colouring in parts with one pass, and for PDF
  text positions, search and selection.
- Scripted end-to-end checks of the real window: 166 on Windows 11, 154 on Linux,
  142 on macOS.
- On a Pixel 10 Pro: the phone layout in both orientations, menus and sheets, typing,
  Notes, a live stream from a web address, PDF files (open, search, password),
  PDF export, printing, and frame timings at 60 and 120 Hz.
