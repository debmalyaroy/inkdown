Inkdown 1.3.4 makes sharing, exporting and text selection on Android work the way they do in other apps, and fixes a corrupted copy of PDF files.

## Downloads

| Platform | File | Status |
| --- | --- | --- |
| Windows 10 / 11 x64, installer | `Inkdown-Setup.exe` | Stable |
| Windows x64, portable | `inkdown-windows-x64.exe` | Stable |
| Android 8+ (arm64, x86_64) | `inkdown-android.apk` | Beta |
| macOS 11+ universal | `Inkdown-macos-universal.dmg` | Preview, UI checks run on a Mac in CI |
| Linux x86_64 | `inkdown-linux-x86_64.tar.gz` | Preview, UI checks run in a container |

`SHA256SUMS.txt` lists the checksum of every file. Windows 1.0.1 and later update
themselves (*Help > Check for Updates*). The Android package installs over 1.0.3 and later.

## Fixed

- **"Save a copy to Downloads" of a PDF wrote an empty file.** The copy was made from the
  document's text, and a PDF (or a picture) has none, so the result had the right name
  and could not be opened. The copy is now the file itself, byte for byte.

## Android: sharing and exporting

The *Share and export* sheet now does what the same sheet does in other apps.

- **Share this file** opens the system's share sheet with the document, to send it to
  mail, a messenger, Drive, or any app that accepts it. The app that is picked can read
  that one file and nothing else.
- **Share as PDF** makes a PDF of a Markdown, text or source document first and shares that.
- **Save as PDF / Word / web page / rich text / picture** open the system's own *Save*
  screen, so you choose where the file goes (Drive, Downloads, any folder). Until now
  exports were put in `Downloads/Inkdown` without asking.
- The sheet offers what applies to the document that is open: a PDF can be shared or
  copied; a Markdown document has the whole list.
- Sharing works for read-only documents such as PDF files, where it used to be refused.

## Android: receiving from other apps

Inkdown now appears in the share sheet of other apps. A shared file is opened; shared
text becomes a new note, named after its subject.

## Android: selecting text

- **A long press selects the word** under the finger, as a double tap already did.
- **Cut, Copy, Paste, Select all and Line** appear in a bar above the keyboard whenever
  text is selected; after a long press on an empty place the bar offers *Paste* and
  *Select all*. These actions existed before only as icons at the far end of the
  formatting strip, where they had to be found by scrolling it.

## Known limits

- Text cannot be selected in Read mode; a long press does nothing there. Copy from Write
  or Markdown mode.
- There are no handles to drag at the ends of a selection: use *Line* and *Select all*
  to widen it.
- On Android, an emoji in an exported PDF is drawn as a black box.
- The rest is unchanged from [1.3.3](v1.3.3.md).

## Testing for this release

- On an Android 15 emulator, with a build of this version: Back through all its steps;
  sharing a document and a PDF and reading them back in the receiving app; *Save a copy
  to Downloads* of a PDF and *Save as PDF* through the system screen, with the files
  checked by an independent PDF library; receiving a shared file and shared text; double
  tap in the reader and in a PDF; long press, the selection bar, copy and paste, Undo;
  unsaved work after the app was killed; rotation.
- New scripted checks of the real window in the phone layout: sharing (6), long press
  and the selection bar (3). All unit tests and the whole suite on Windows, and in CI on
  Linux and macOS.
- **Not checked on a physical phone**: none was connected. Two-finger pinch, the feel
  of scrolling and predictive text can only be judged there. On the emulator, typing key
  by key, Find, Notes, web addresses and Print were not repeated for this version.
